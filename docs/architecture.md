# Архитектура проекта (фундамент)

Версия: 1.0 (2026-09-11). Базовая платформа: dicio-android (форк `volodymyr-1/dicio-android`).
Целевое устройство: Samsung Galaxy Tab A7 Lite (SM-T220), см. `docs/device-audit.md`.

## 1. Целевой голосовой контур

```
WAKE («Hey Dicio» → цель: «ассистент»)
  └─ WakeService (OpenWakeWord, tflite)
LISTEN
  └─ Vosk small-ru (freedom dict), silence=6 (настройка sttSilenceDuration, 1..7)
ROUTE (SkillEvaluator + IntentRouter)
  ├─ 1) STT-коррекции (словарь оговорок: «сечас»→«сейчас», ...)
  ├─ 2) Negative-guard (не/нет/почему/жалобы → не выдавать интент)
  ├─ 3) Exact-интенты «сквозных» команд → мгновенный статичный ответ
  │      (привет/пока/спасибо/умеешь/громкость/UNSUPPORTED-честный отказ)
  ├─ 4) Свободные навыки (dicio skills: время/погода/таймер/...)
  └─ 5) Fallback (TextFallback: «Я не поняла/Можете повторить?»)
SPEAK
  └─ TTS-движок (сейчас: системный Android TTS; цель: качественный ru-движок)
FOLLOWUP (окно продолжения, позже)
```

## 2. Принципы (закреплено)

1. **Роутер — только «сквозные» мгновенные ответы.** Тяжёлая логика — в навыках
   (SkillInfo/Skill системы Dicio). Роутер не должен знать доменные подробности.
2. **Одна фраза — одна команда.** Многословные сценарии (расписания, «на будни и выходные»)
   — это отдельные навыки с уточнениями (sub-interaction), не обязанность роутера.
3. **Честность ответов.** На понятную, но нереализованную команду — осмысленный отказ
   («Я пока не умею...»), не «Можете повторить?» (интент UNSUPPORTED).
4. **Русский по умолчанию.** Локаль RU, ответы и фразы — русскоязычные.
5. **Наблюдаемость.** Все ключевые события — в `DiagnosticsLog` (буфер + файл
   `filesDir/diagnostics.log`, чтение: `adb shell run-as <pkg> cat files/diagnostics.log`).
   Android logcat на этом устройстве не выводит `android.util.Log` приложения — файл является
   единственным надёжным каналом.
6. **Развёртывание.** CI (GitHub Actions) → APK artifact → `adb install` (uninstall при смене
   подписи; permission сбрасываются — выдавать заново).

## 3. Решения (ADR, сокращённо)

| # | Решение | Статус |
|---|---|---|
| ADR-1 | Язык по умолчанию: русский (локаль RU) | принято |
| ADR-2 | STT: Vosk small-ru (проверен в бою), Silero — кандидат «движок 2.0» | принято (Silero отложено) |
| ADR-3 | TTS: качественный системный ru-движок (RHVoice/Supertonic-3) как в smartnote; код Dicio не меняем | принято (реализация отдельно) |
| ADR-4 | Wake word «ассистент»: обучение кастомной openWakeWord-модели (Python); временно «Hey Dicio» | отложено (по решению пользователя) |
| ADR-5 | Свои навыки (одежда/будильник) — поверх skill-системы Dicio | принято |
| ADR-6 | Диагностика — файл+буфер (logcat непригоден на устройстве) | принято |
| ADR-7 | Брендинг/имя «Смарт» и UI — после стабилизации ядра | отложено |

## 4. Структура собственного кода

```
app/src/main/kotlin/org/stypox/dicio/
  util/DiagnosticsLog.kt      — кольцевой буфер + файл (канал наблюдения)
  util/Similarity.kt          — нормализация/нечёткость (для словарей)
  eval/IntentRouter.kt        — детерминированный роутер «сквозных» интентов
  eval/SkillEvaluator.kt      — точка встраивания роутера (до SkillRanker)
  io/graphical/StaticReplySkillOutput.kt — мгновенный статичный ответ
  io/nav/Drawer.kt            — UI-панель «Диагностика»
app/src/main/sentences/ru/    — русские фразы навыков (timer.yml и др.)
```

## 5. Тесты и качество

- Юнит: `IntentRouterTest`, `SimilarityTest` (Kotest) — гоняются в CI.
- Боевые тесты: вручную на планшете, протокол и результаты — `docs/tests/battle-log.md`.
- Гигиена: `.editorconfig` + ktlint — следующий этап (борд `docs/plan.md`).
